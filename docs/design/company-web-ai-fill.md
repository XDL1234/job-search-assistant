# 公司网申 AI 填写设计

桌面版默认将填好的岗位表单保留在求职专用 Chrome，用户可逐家核对并自行提交。创建任务时也可以单独授权自动提交。Codex 按当前页面判断下一步，本机浏览器工具处理标签绑定、原始资料写入、附件和提交回执。

## 一次任务怎么用

1. 用户导入公司表，预览本轮公司、岗位、资料版本和简历附件，选择「仅填写，我来提交」或「填写并自动提交」。默认选中前者。
2. 点击「打开本批网页」。助手将全部有效行按原表顺序加入队列，用求职专用 Chrome 打开本批网站。用户可以在各标签间扫码或登录。这个阶段只需要 Chrome。
3. 点击「我已登录，开始填写」。助手复查本批原标签，保留表格顺序，逐家处理当前能够填写的岗位。准备网站、等待用户时不调用模型。需要 Codex 而连接尚未就绪时，保留已打开的页面，显示「连接 Codex 后继续」。
4. 在默认模式下，每填好一家，就保留其表单和标签，工作台提供「打开核对」。队列继续处理其他可填写公司。点「继续」只授权继续检查和填写，提交权限始终取自已确认的任务。

例如，表里第一行是阿里巴巴、第二行是北汽。若阿里仍要求扫码、北汽已可填写，助手先填北汽。用户补登阿里后再点「继续检查」，队列重新从排在最前的未完成行开始，北汽已填表单保持原样。两家都要求登录时，工作台列出两家公司和「前往登录」按钮，任务暂停等待。

## 工作台

| 位置 | 内容和操作 |
|---|---|
| 顶部 | 显示任务名、填写模式、可填写家数、待登录家数、已填写待核对家数。准备阶段的主按钮是「我已登录，开始填写」，恢复阶段是「继续检查」。 |
| 左侧队列 | 固定原表顺序，显示公司、目标岗位、当前状态和原因。按状态提供「前往登录」「打开核对」或「补充资料」。未打开的网站显示「尚未打开」。 |
| 右侧预览 | 填写期间显示助手正在操作的公司、岗位及绑定标签的实时画面。登录或身份核验阶段显示待办提示，用户在 Chrome 完成操作。点击「打开核对」激活对应标签。 |
| 本轮结果 | 分开统计「已填写待核对」「用户标记已提交」「已核验提交」「提交待核查」。用户手动标记和网站回执保留各自的来源。 |

## 批次与内存

同时保留最多 **5 个任务工作标签**，一次最多加载 2 家，任一时刻只允许 1 家执行填写。公司数不超过 5 且内存充足时，一次操作即可全部打开。更长名单一次性入队，后续点击继续时按原表顺序补充空位。复用时校验浏览器会话和该行的标签绑定。

开下一页前读取 Windows 可用物理内存。低于 **2 GiB** 时暂停新增网页，仍可处理已打开页面。阈值为保守默认值，各招聘网站的实际占用会随页面内容变化。待人工核对的标签、跟随申请流程保留的额外窗口也占用容量。若全部位置被占用，先核对并关闭已处理的网页，再打开下一批。尚未打开的公司继续显示「尚未打开」。

## Codex 如何找到真正的表单

| 步骤 | Codex 的判断 | 浏览器工具执行与核对 |
|---|---|---|
| 找岗位 | 从当前页识别校招、实习、职位列表、搜索入口，按本轮岗位和已有约束匹配候选项。多个结果无法区分时，请用户选定。 | 打开观察到的链接，使用本轮岗位关键词搜索，读取岗位详情。表格直达对应表单时跳过搜索。 |
| 进表单 | 区分「去完善简历」「进入申请」与可能立即送出申请的「一键申请」。根据按钮、所在区域、上下文判断用途。 | 仅点击已确认的导航或编辑控件。首次跳到新招聘平台时，记录从哪一行、哪个控件跳出，核对公司、岗位和目标站。共享招聘域名还要核对租户或职位标识。关联不足时交给用户确认。 |
| 认字段 | 对照栏目、标签和第几段经历，将控件匹配到资料路径。例如教育经历第一条的「毕业院校」对应 `profile.education.0.school`。 | 凭本次页面快照和控件编号读取本轮已保存的原值，写入空白必填框，选择对应选项或上传绑定的简历。已有值保留，选填项默认跳过。 |
| 处理动态页面 | 判断是否要展开栏目、新增一段经历、选取联想结果或切到下一步，并识别网页校验提示。 | 页面跳转、弹窗、新增条目或选择完成后重新观察。核对已存在的经历再新增，写入后读回实际值。控件失效则废弃旧编号。图片仅用于即时判读，不写入截图留档。 |
| 结束填写 | 核对当前公司、岗位、必填项、附件名和页面错误。 | 仅填写模式在最终提交前停住，标「已填写待核对」。自动模式在通过核对后登记一次提交，点击后验证回执；无明确回执则标「待核查」。 |

登录按**能否继续这份申请**判断。在实际入口明确要求登录或验证码时，转为「待登录」。页面显示已登录身份，或目标表单明确允许免登录填写时，可继续。公开招聘首页同时出现「登录」与岗位列表时保留为「需定位入口」，允许 Codex 先只读导航。碰到可能直接提交的按钮、无法验证的跨域表单或缺失的必填资料，转为「需人工处理」，并继续检查其他公司。

缺少必填资料时，可以在原网页补好该项，再点击「继续检查」。如果选择在助手的「个人信息」中保存新资料，还需要在工作台「编辑任务」并确认新的材料版本，随后 AI 才会使用这份资料。

「填写完成」的依据是已核对的目标表单。多步页面须检查已到最后的核对页，或网站已明确显示该岗位草稿完整。仅填写模式下，工具可以根据明确的最终只读核对页完成交接。附件检查网页回显文件名或上传成功状态，重复经历核对学校、单位和日期。连续两次观察没有进展且没有新的安全操作时，记录卡住的步骤，由用户接管。

## 队列与恢复

| 每行状态 | 进入条件 | 下次继续时 |
|---|---|---|
| 待打开／待检查 | 入队或刚打开网站 | 打开或重用该行已绑定的标签，检查当前页面 |
| 待登录 | 遇到明确登录或验证码要求 | 用户点击继续后原位重查，无需重新导表 |
| 待定位／填写中 | 可浏览岗位或已有可编辑表单 | 重新观察公司、岗位和当前表单，再从缺失项继续 |
| 需人工处理 | 缺必填资料、多个岗位无法区分或控件有歧义 | 在用户补充或选择后重查对应行 |
| 已填写待核对 | 人工模式完成核对 | 保留标签，跳过自动填写；若标签关闭，提示网页草稿状态未知，由用户决定是否重新打开检查 |
| 已提交／提交待核查 | 自动模式有明确回执／提交动作已执行但结果不明 | 使用既有提交台账，恢复时禁止再次点击 |

按行持久化任务编号、表格版本、原始行号、公司和授权岗位、状态、原因、最近检查时间及关联申请编号。浏览器会话内保存行到标签的绑定；浏览器重启后标签编号可能失效，须重新核对，不能仅凭相同域名接管页面。恢复前检查本轮控制代际和提交台账，防止旧执行器继续写入。等待登录记录与申请结果分开，登录前不创建申请失败或最终跳过记录。

队列沿用公司级防重复申请规则。同一家公司列有多个岗位时，若前一行已有待核对草稿、已提交或有未决结果，后续岗位会显示跳过及原因。不同公司共用招聘平台域名时，仍各自核对公司、租户与岗位。

执行器按一次「继续」检查一轮，遇到障碍后继续下一行，避免在同一家循环刷新。所有已打开网页都需登录时暂停等登录；已填写表单占满工作位时等待用户核对；所有行都已填写或有明确结果时停止自动操作，仍有待核对项则显示「填写结束，待你核对」。若应用重启、网页关闭或表单未保存，重新观察网站实际内容，不把本地记录当作网页草稿。

如果 Codex 在处理完一家公司后结束回合，执行器会读取当前批次的台账。只要可处理的行数已经减少、还有公司可填，便自动接续下一回合。可处理行数没有减少时，暂停并显示未完成的公司，避免反复请求模型。

## 实施顺序

1. **准备和恢复。** 在现有 `TaskSetup`、`Workbench` 增加批次入口和行状态。Rust 浏览器层在 Codex 启动前准备标签，并把实时预览绑定到当前处理行。Python 台账增加可恢复的登录队列，沿用既有授权与防重复规则。
2. **打通不同网站的填写。** 复用 `observe / click / scroll / fill / upload`，补上按授权关键词搜索，以及申请按钮打开新标签后的绑定与核验。Codex 每次根据真实页面选下一步，无需预先为每家公司编写一份表单脚本。
3. **完成与异常收尾。** 将当前「仅填写完成即暂停整轮」改为「当前行待核对，继续下一行」。自动提交继续通过现有单次动作和回执检查。任务编辑、重启、失效标签和不明确回执均从台账恢复。

## 首版验收

- 用两个隔离模拟站点走正常入口。A 从招聘首页搜索岗位，新增教育经历后字段出现；B 从岗位详情打开新标签，包含联想学校控件和一条已有经历。两者使用同一套浏览器工具。
- 混合登录状态时先填可处理公司，补登后再填另一家；全部需要登录时列出具体公司并暂停。公开首页无账号信息但表单允许直接填写时，能继续到表单。
- 默认仅填写模式，两个站点提交计数均为 **0**，填好的页面都能打开核对。已有内容、选填项和不明确的必填项符合前述规则。
- 自动提交模式用模拟回执验收。明确成功只登记一次；点击后断网或无回执进入「待核查」，重启或再次恢复后提交计数仍为 **1**。
- 导入 12 家时，默认不同时打开 12 家。模拟低内存、关闭标签、应用重启和共享招聘域名的不同公司，验证队列顺序、草稿保留策略、目标归属和下一批补位。
