# BOSS 后台执行与浏览器连接器

本轮采用桌面应用＋Chrome Manifest V3 扩展。桌面应用保存资料、授权和投递台账；扩展只操作当前用户已登录的 BOSS 标签页。脚本完成推荐结果筛选与沟通步骤，AI 只用于精筛和需要语义判断的工作。

## 首次连接

1. 安装桌面测试版，保持原 Chrome 登录状态。
2. 在 Chrome 打开 `chrome://extensions`，开启开发者模式，选择“加载已解压的扩展程序”，选择应用安装目录里的 `browser-extension` 文件夹。Windows Chrome 不支持本项目静默安装未上架扩展，安装器不会改写浏览器策略。
3. 桌面应用“设置与帮助” → “启动浏览器连接器”，复制本机连接码。
4. 点击 Chrome 扩展图标，把连接码粘贴进去并连接。进入 BOSS 推荐或搜索页，保留当前城市和筛选；多个 BOSS 标签页时，首次开始前选中目标标签。
5. 导入并保存简历资料，在 BOSS 投递页选择求职类型、投递模式与上限，预览并确认，再从工作台开始。

连接码只用于回环地址认证，不发给招聘网站或模型。应用重启会尽量复用端口和密钥；端口被占用时会报错，不连接未知服务。升级扩展文件后，在 Chrome 扩展管理页刷新扩展。

## 三种 BOSS 模式

| 模式 | 工作方式 | 模型调用 |
|---|---|---|
| 平台筛选 · 脚本快速沟通 | 保留平台筛选，核对卡片方向/求职类型，按顺序开聊，记录回执与截图 | 不启动 Codex，不使用模型 token |
| 平台筛选 · AI 操作 | 模型观察平台结果并通过受控浏览器工具操作 | 使用 Codex |
| AI 精筛 | 阅读岗位描述并判断适配后投递 | 使用 Codex |

实习、校招、正式工作是不同配置，当前简历不因切换类型而被改写。公司官网仍使用独立公司表与 desktop computer use，逐字段记录和截图；官网实测按用户安排后置。

后台表示无需把 BOSS 窗口置于最前，也不通过鼠标坐标抢占桌面。电脑休眠、Chrome 关闭或应用退出会中断；应用退出先暂停，重启需用户恢复。未上架连接器仍需首次手动加载，本版不提供手机端或断电后继续运行。

## 动作与留档

- 本机桥接只监听 `127.0.0.1`，所有请求需要随机密钥，普通网页来源被拒绝。
- 每个输入前重新检查任务租约、材料版本与停止状态；发送还需已登记且已消费的动作。超时结果不明记为待核查，禁止盲目重发。
- 岗位通过正常 DOM 与标签页导航操作，不读取 Cookie、账号密码、网页私有接口，不绕过验证。
- 扩展的 `debugger` 权限用于针对绑定标签页取得实际 PNG 截图；不把 DOM 文本渲染成假截图，也不截取用户其他标签页。若 DevTools 占用了调试通道，截图可能失败，动作会转为待核查。
- 平台要求验证、限制访问、页面无法唯一确定按钮时暂停，不靠高频重试解决。
- 首次开聊沿用平台话术。面试始终转人工；回复规则保存不发送，也不解除人工会话锁。

## 当前验证边界

2026-11-17：本机实际应用已通过真实简历导入、九种类型/模式组合的预览、网申入口保留、回复条件校验、原生桥接启动与关闭检查。Python 领域、桥接协议和扩展边界已作自动化检查。

实际窗口测试曾复现“规则读取尚未完成就新增，稍后旧结果覆盖新内容”，已通过加载期间禁用编辑修复并重新验证。资料页使用相同加载保护。回复条件使用薪资与城市表单，用户无需编写 JSON。

**当前 Chrome 尚未加载此新连接器，因此后台 BOSS 的真实 DOM 选择器、实际沟通、附件发送与后台截图仍未在用户账号验收。** 网申真实网站也尚未验收。源代码和界面可用不等于真实网站已通过；测试版发布说明需保留这一区别。
