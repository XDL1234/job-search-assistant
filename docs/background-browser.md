# BOSS 浏览器连接与 JPEG 预览

当前源码已将旧 MV3 扩展＋Python 桥接替换为固定 agent-browser v0.43.0 原生运行时。桌面应用保存资料、授权和投递台账；脚本完成确定步骤；JPEG 经 Rust/本机 Channel 直接送入工作台，不经过模型或 Python。已发布 beta.4 的旧安装包仍按其[版本说明](releases/v0.3.0-beta.4.md)使用扩展，不能与新源码的连接步骤混用。

## 首次连接

1. 安装 Chrome 后，首次打开支持此流程的求职助手。应用会打开并连接求职专用 Chrome，在窗口中打开 BOSS 直聘。
2. 只有一个可用 BOSS 标签时，应用会自动绑定。需要登录时，请在专用 Chrome 完成登录，再从左侧打开「连接与诊断」，点击「刷新标签」并选择 BOSS 标签。
3. 专用 Chrome 的登录状态保存在独立资料目录。再次打开应用时，若专用窗口仍在运行，应用会重新连接。窗口已关闭时，可以在连接设置里点击「连接 Chrome」重新打开。
4. 从左侧打开「简历」和「个人信息」保存资料。新建投递后设置并确认范围，再从工作台开始。

## 岗位条件

在新建投递的 BOSS 页面点击「编辑岗位条件」。基本条件里可搜索城市名称或拼音，也可按省份浏览。高级筛选里点开「职位分类」或「公司条件」，从目录中选择职位和行业。选择城市后，可在「工作区域」指定行政区和商圈，或地铁线路和站点。

保存后可点「在 BOSS 核验」。应用在已绑定的 Chrome 标签操作实际菜单，并在重新加载岗位列表后逐项核对。需要完整筛选栏时可填写搜索关键词。校招对应平台「全职」和「应届生」，实习、兼职和不限对应各自的平台选项。兼职页的「结算方式」和「兼职时间」由 BOSS 页面设置。

BOSS 三种投递模式均可使用已保存条件，或沿用已绑定标签页的实际筛选。岗位方向留空时使用已保存资料中的岗位方向。选择已保存条件时，启动先应用并核验确认的范围。公司网申先读取公司表，并在预览中列出本轮可用公司。

应用每次启动使用新的运行时会话和随机密钥，命令入口与只读媒体入口均认证。密钥不写入界面状态、浏览器描述符或模型上下文。连接丢失后停止，不自动启动另一个浏览器；应用关闭只结束本应用会话，保留用户 Chrome。

## 三种 BOSS 模式

| 模式 | 工作方式 | 模型调用 |
|---|---|---|
| 平台筛选 · 脚本快速沟通 | 保留平台筛选，核对卡片方向/求职类型，按顺序开聊，记录回执与截图 | 不启动 Codex，不使用模型 token |
| 平台筛选 · AI 操作 | 脚本收集卡片，模型对小批真实字段返回结构化选择，脚本执行 | 使用 Codex，无持续视觉观察 |
| AI 精筛 | 脚本打开详情，模型对完整岗位事实判断，发送前重新核对 | 使用 Codex，判断缓存绑定完整事实 |

实习、校招、正式工作和兼职是不同配置，切换类型时继续使用本轮固定的简历。

公司网申先在求职专用 Chrome 打开本批网页。用户完成各站登录后，点击「我已登录，开始填写」，助手按表格顺序检查，只将本次可处理的公司交给 Codex。默认「仅填写，我来提交」会保留每份表单供核对，继续处理本批其他公司。选择「填写并自动提交」后，按任务授权提交并核对回执，结果不明时转为待核查。实时预览只显示正在处理的岗位，登录和验证码在 Chrome 内完成，网申画面仅供即时查看。

## 消息与人工处理

脚本快速沟通在确认发送回执后回到原列表，达到沟通上限或列表结束时完成任务。需要处理招聘方的后续消息时，从工作台单独开启「消息值守」。只有简单完整问句能够直接匹配规则，金额单位等信息不清楚时转人工。未知问题选择 AI 模式后，需要连接 Codex，未连接时保留待办。

面试整条消息转人工并请求系统提醒。「待办」可保存处理意见。发送前先打开并核对会话，再复核原文和正文并单独确认。发送后可继续人工处理，恢复自动回复需另行确认。索要简历时使用本轮绑定的原附件，入口或新增附件回执不明确时转人工。

在求职专用 Chrome 切到其他标签时，工作台仍从已绑定的 BOSS 标签读取当前视口，每帧都等待界面确认。隔离 Chrome 测试核对了隐藏期间的页面变化和切回后的首个新画面。既有窗口后台测试也验证过正常窗口被遮挡时可以继续预览。Windows 窗口最小化后的连续性尚待验证。

BOSS 的发送结果依据目标会话的回执和独立留档。桌面公司网申按页面回执登记结果，实时预览仅供查看。电脑休眠、Chrome 关闭或应用退出会中断执行，重启后可在工作台恢复未完成的任务。

## 动作与留档

- 原生运行时仅在回环地址提供认证入口；内嵌模式关闭 HTTP 服务与媒体输入，只允许配置、帧与 ACK。
- 每个输入前重新检查任务租约、材料版本与停止状态；发送还需已登记且已消费的动作。超时结果不明记为待核查，禁止盲目重发。
- 岗位通过正常 DOM 与标签页导航操作，不读取 Cookie、账号密码、网页私有接口，不绕过验证。
- CDP 针对已绑定标签取得实际 PNG 截图；不把 DOM 文本渲染成假截图，也不截取用户其他标签页。截图失败、标签变化、旧控制代际或实际结果不明时停止，发送不盲目重试。
- 平台要求验证、限制访问、页面无法唯一确定按钮时暂停，不靠高频重试解决。
- 首次开聊沿用平台话术。面试始终转人工；回复规则保存不发送，也不解除人工会话锁。

## 最新版本与迁移验证

浏览器底座及其验收边界见 [beta.10 说明](releases/v0.3.0-beta.10.md)。当前[界面测试版](releases/v0.3.0-beta.12.md)沿用该底座。以下为 beta.5 原生浏览器迁移时的历史记录。

2026-11-18 新底座：已完成固定来源构建、认证与只读流、ACK 最新帧、非首标签绑定、关闭/离域停止和旧订阅保护的隔离 Chrome 检查。真实用户 Chrome 已完成原生配对；真实 BOSS 的脚本模式、平台推荐 AI 模式、AI 精筛各完成一次开聊，台账均为 `greet=succeeded`，三轮任务全部暂停。精筛本轮使用 1 个 turn，input 6277、output 234、total 6511 token，图片数为 0。开聊成功不代表附件、回复或网申已通过验收。固定运行时与补丁哈希见 [JPEG 设计](design/jpeg-stream-agent-browser.md)，详细进度见[五轮迭代记录](superpowers/plans/2026-11-18-agent-browser-iterations.md)。

精筛实测发现外层详情文本混入动态页脚，导致模型接受后反复进入 `changed_return`。现只提取职位描述区域与岗位标签，保留完整 JD，不按字符截断；该岗位外层文本 1778 字符，JD 为 325 字符、7 条要求完整，两次导航后内容一致。真正的岗位事实变化仍会阻断发送。

迁移早期曾复现连接后 BOSS 变为 `about:blank`，当时的 guard 已阻断业务动作；后续修订的固定运行时已完成上述三次真实开聊。不能仅凭早期对照确定站点检测机制，也不能把它继续列为当前版本所有投递均不可用的结论。

Codex 启动现会读取当前用户静态系统代理，仅为其子进程补充缺失环境变量；显式代理设置（含空值）优先，不修改全局环境，配置不进入界面、模型或日志。清空开发环境与代理环境变量后，真实受限 `outputSchema` 请求在 5.908 秒完成，返回 JSON 匹配且未调用工具。该修复已纳入本轮重新冻结的 worker，不新增 PAC 支持。

beta.5 最后一轮修复及独立审查通过，自动化检查为 Python 206 通过、4 跳过，前端 9 项和 Rust 26 项通过。该版本的 NSIS 在开发机原路径升级，2,286 项资源核验一致。清空开发 PATH 后的快捷方式、导出、Codex 连接、真实 Chrome 岗位详情和实时画面均通过。安装器哈希见 [beta.5 说明](releases/v0.3.0-beta.5.md)。

## 旧 beta.4 与更早验证记录

以下为旧扩展版本的历史边界，不代表 beta.5 的当前聊天适配状态。

2026-11-17：本机实际应用已通过真实简历导入、九种类型/模式组合的预览、网申入口保留、回复条件校验、桥接启动与关闭检查。Python 领域、桥接协议和扩展边界已作自动化检查。

实际窗口测试曾复现“规则读取尚未完成就新增，稍后旧结果覆盖新内容”，已通过加载期间禁用编辑修复并重新验证。资料页使用相同加载保护。回复条件使用薪资与城市表单，用户无需编写 JSON。

2026-11-17 后续实测：用户完成扩展连接后，已在已登录 Chrome 验证当前双栏卡片、滚动加载和三种模式各一次真实开聊；有目标回执和截图，已暂停测试，没有发送附件或进行网申。实测发现并修复卡片字段、慢回执和导航等待问题。

**当前账号的聊天列表结构仍需适配，自动回复/值守暂不能作为已验收功能开启；识别失败时会明确停止。** 附件、预设问答、面试接管和真实网申尚未通过实站验收。开聊成功不能代替这些检查，具体见 [beta.4 说明](releases/v0.3.0-beta.4.md)。
