# 官网网申

## 岗位选择

公司来源仅为本轮授权的用户表格。每行至少有公司和 HTTP/HTTPS 申请入口，可包含具体岗位。先 `companies` 读取并确认列映射；入口跳转到 ATS 时从公司官方链接核验承接关系。

有指定岗位就处理指定岗位；否则搜索本轮确认的方向/岗位名及别名。读取岗位职责与硬性要求，使用个人资料与偏好分析适配。每家公司只选最匹配的一个。硬条件未知应进一步查看或转人工，不能把未知当满足；没有额外硬条件时也须核对招聘类型和岗位方向。

可将候选及模型评估传给 `select_job`：`mode=screened`，`evaluation.hard_conditions` 为逐项 `yes/no/unknown`，`fit` 0–100 仅用于排序。为每项保留页面证据和判断理由，分数不是录用概率。

没有合适岗位也要创建尝试（job 与 job_key 使用明确的“无匹配岗位”描述），归档当前搜索结果截图，记录 `no_match`。坏链接、登录失败、公司重复同样进入结果表；已有记录可引用，不新开重复动作。

## 填写与完整截图

1. 创建 `begin`，获得 attempt_id。检查历史，同公司已有成功、待核实或待人工尝试时不再次投递；恢复原尝试。
2. 读取页面字段，按确认的 profile 映射填写。`field` 记录字段名、实际填写值和资料出处。下拉框选择语义相同的真实选项，不随意选“其他”。必填缺失时记录 needs_user，询问并继续其他公司。
3. 上传既有简历，先 `verify_materials`，核对文件名、版本与页面上传状态。自动保存也属于本轮已授权的个人信息传输。额外协议、未经指定的证明材料或支付操作转人工。
4. 每一步填写完成后，`capture` 并实际查看。长页面按视口滚动截图，避免漏掉下半页；滚动 textarea 内部以记录长文本。将每张原图经 `evidence` 归档。
5. `fields` 参数只列该截图能完整证明的字段。跨多截图字段先存中间截图，最后确认全覆盖后关联最后一张；所有同 attempt 的截图和字段索引共同构成证据。内容被遮挡、截断时不能声明覆盖完成。
6. 字段修改后重新 `field`（清除旧覆盖）、重新截图。不能只留提交后的成功页。
7. 全字段和简历状态核对完成，保存 kind=pre_submit 的最终复核截图。`prepare submit` 提供该 evidence_id，登记 pending 后才点击最终提交。
8. 输入动作返回新截图不代表提交成功。读取回执/申请编号/投递历史；另存 kind=result 的截图，`finish succeeded` 描述可见凭据。

## 异常和恢复

无论成功失败都留真实现场与原因。提交后超时记 uncertain，先去历史核查；只在明确证据证明未执行时 `finish not_done`，之后才可重新登记操作。不能从 uncertain 直接盲重试。

验证码、身份验证交给用户，暂停相关输入与敏感登录截图。用户接管桌面前 `control paused`。暂停单家公司用 needs_user；不影响已授权其他公司。截图/磁盘/桌面等公共能力故障应暂停本轮，不能无证据继续。

每家公司结束或中断即导出结果表，保持原始输入表格不变。报告 status、reason、申请页、岗位、实际填写值、截图位置。所有时间源存 UTC，向用户展示按 Asia/Shanghai 转换。
