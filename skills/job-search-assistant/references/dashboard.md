# 本地可视化面板

需要用户观察进度或控制任务时使用。无需前端构建工具或新运行依赖，静态资源随 Skill 分发。

```powershell
& "<python>" -X utf8 "<skill>/scripts/run.py" --root "<data>" dashboard --open
```

命令持续运行，默认随机空闲端口，仅监听 `127.0.0.1`。自动打开的地址包含本次访问凭据，保存在 `<data>/dashboard-session.json`；不要分享这个地址或日志。运行面板服务时不要占用模型的长时间阻塞等待；宿主可使用进程会话或 Windows `Start-Process -WindowStyle Hidden` 启动。用户也可使用发行包 `open-dashboard.ps1`，保持终端打开，Ctrl+C 关闭服务。关闭浏览器标签不结束该面板服务，关闭面板服务也不等于停止投递，停止任务使用面板的“停止”。

## 执行器如何配合

- 新建任务：用户填路径/导入配置，预览包括材料哈希的完整快照，勾选确认后创建 run_id。面板只登记授权，不启动 Codex。用户给出该编号时读取 `status`，沿用已有轮次和授权，不再次 `start`，先 `verify_materials` 和 `tick`。
- 暂停/停止立即持久化，后续 `check_run` 拒绝操作；无法撤回已经发送的点击。失败或未完成提交按原规则核实。
- 继续/仅值守进入命令队列，带 run_id 的下一次执行请求先消费并复核材料。恢复后旧截图失效，必须 `capture`、实际查看图片，再输入。`status` 查询本身不会消费指令。
- 面板打开或轮询不产生执行心跳。显示的活动只是最近一次工具调用，不能推断当前模型仍在线。每次 `tick` 返回 `human_notes`，`status` 包含 commands、activity、notes 与最近画面。
- 暂停时允许只读 `status` 与当前会话可中断等待。看到 pending 继续指令后，通过 `tick` 接收；新截图仍需浏览器回到正确页面。面板抢占前台时不能自行对其输入，等待用户回到招聘标签。
- 人工意见只记录在 attention_notes，不属于已批准发送的消息，不能自动复制发送。面试邀约仍锁定；用户在 BOSS 完成人工沟通后，通过“已处理，恢复此会话”明确解锁。保存意见不会解锁。消息变更会使旧的恢复请求失效。

## 页面范围

概览显示选中轮次计数、最近行动与配置。截图是该数据目录内最近一次浏览器观察，带时间，不是直播，也不承诺属于选中历史轮次。投递记录按轮次筛选并含附接的历史申请；点击详情查看字段来源和证据。待人工事项与 Excel 导出覆盖整个数据目录的全部轮次。

如网络断开，页面禁用运行控制并保留最后一次显示数据。面板不提供任意 shell、任意文件下载或直接发送接口。尚未做对公网、多用户部署的设计，不修改监听地址对外开放。
