# BOSS 投递与回复值守

## 投递前

使用用户已登录的 Windows 网页端，核实本轮筛选条件与平台当前限制。不得读取私有接口、绕过验证或用高频重试规避限制。绑定窗口后，通过截图理解 UI；本技能没有假设永远不变的坐标或选择器。

两种模式每轮二选一：

- `filtered`：核验用户设置的城市、职位方向等筛选，顺序处理推荐卡片，不打开职位详情做适配判断。只识别职位/公司/招聘方、是否已经沟通以及可操作状态。需要比平台筛选更细的条件时提示用户改用 screened，不偷偷扩大此模式职责。
- `screened`：阅读职位描述，按明确需求、预期和 profile 判断；先检查硬条件，再排序。未知项影响关键条件时不投递。记录依据。

## 开聊与附件

1. 为新岗位创建 begin。job_key 使用平台能读取的稳定职位 ID 或岗位链接；无法得到时使用公司、职位、招聘方组合并记录识别依据，不用当前列表序号。
2. 核查是否已沟通，`prepare greet` 后以 commit 触发“立即沟通”。这一步使用平台既有话术，不输入另一段开场白。
3. 核查聊天会话/平台消息，归档结果并 finish。没有显示话术时不补发，不假设触发成功，先核实。
4. 首次不主动发附件。收到索要消息或简历请求卡片时记录原消息及其稳定 key，按下述路由判断。核验附件与本轮 resume_sha256 一致。
5. prepare resume 的 payload 包含 requested=true、resume_sha256、message_key。附件选择若只是本地选择用 fill；一旦上传/确认会立即发送则该动作就是 commit。若平台存在后续独立确认按钮，分别核验，不凭空认为附件已发送。

## 消息语义分析

读取同一会话最新完整上下文和连续未处理消息，避免只截取一条。原文与消息 key 调用 route_message 保存。key 应包含可见时间/消息序号或稳定标识，重复正文在不同时间需不同 key。不得让旧消息覆盖最新消息。

由模型提供 `analysis`：

```json
{
  "categories": ["salary"],
  "complete": true,
  "ambiguous": false,
  "interview": false,
  "new_commitment": false,
  "facts": {"salary_monthly_gross": 16000, "salary_basis": "税前月薪"}
}
```

类别支持 interview、resume、salary、location、availability、other，以及用户自定义规则类别。complete 表示所有问题已覆盖，不能为通过规则而填写 true。间接面试邀请、电话面试、改期、确认面试地址都标记 interview；词面匹配只是兜底。

规则的 when 支持 eq、in、gte、lte，所有条件必须同时满足；数值不接受“15k”等字符串。将税前/税后、月薪/年薪、薪资范围、城市/区域区分。信息不够就转人工，不猜测。固定话术不改写，多问题全部有明确匹配规则才可合并发送。

优先级：**面试整条转人工 → 已人工接管保持锁定 → 索要简历 → 完整匹配固定规则 → 非常见问题模式**。混合简历请求和其他问题也先转人工，避免只做一半。

非常见问题：human 模式提醒用户；ai 模式根据 profile 与已确认事实写草稿，列 sources 字段路径，并核查每一事实都被来源支持。代码只验证引用存在，无法替代语义真实性判断。未知、冲突、新承诺、薪资底线调整都转人工；没有证据的礼貌承诺也不自动发送。

将 route_message 的结果用于 prepare。prepare 会再次做规则检查，固定话术必须字面一致；准备后再次查看最新消息再执行 commit。接收方、会话变化时不得使用旧判断。

## 人工与值守

面试或其他需人工消息写入 handoff，锁定整个会话，不自动发“好的”等确认性文字。聊天提醒包含原文、招聘方、公司及记录链接。用户明确指示恢复后 resume_conversation；仅已读或用户暂时离开不能解锁。

默认每 60 秒检查消息；用最多 30 秒一段的可中断等待。轮询时仍须查看聊天列表，不能只依赖未读红点（自动打开会话会清除红点）。只有新消息/状态变化保存证据；不要将空闲轮询每张截图永久归档。一次只允许一个桌面操作队列。投递上限到了则 control watching，只停新增投递，继续回复。

会话结束、桌面失效、用户停止都保存状态。下次恢复先核对 pending/executing/uncertain 的真实平台状态，优先处理人工事项，不重复开聊或发附件。
